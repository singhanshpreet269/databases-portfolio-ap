To verify the LLM-generated query, I wrote task7.py, which runs it against telemetry.db and checks it three ways. The generated query uses time(ts) >= '18:00:00' to keep only evening readings, groups by machine, averages the spindle load and sorts the result in descending order. It ran on the first try and returned plausible averages of about 60.4 for all three machines. I then ran EXPLAIN QUERY PLAN, which showed a full table scan (SCAN readings) because there is no index on ts. To break the query, I compared it with a sloppy LIKE '%18%' version, which matched only 18,102 rows instead of 43,200 because it also catches readings with 18 in the minutes or seconds and misses the hours after 19:00, so its averages were wrong. I also tested a whole-night version (after 18:00 or before 06:00), which gave a different machine ranking, showing that the model silently interpreted “overnight” as only the evening. I verified the correct filter by checking that the row count of 43,200 matches the 6 evening hours across 2 days for 3 machines.
